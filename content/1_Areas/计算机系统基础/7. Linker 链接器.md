## 引言部分
### 我们的代码经历了什么？

**四大阶段：**

1. **预处理 (cpp):** hello.c -> hello.i (文本, 宏展开)
2. **编译 (cc1):** hello.i -> hello.s (文本, 汇编代码)
3. **汇编 (as):** hello.s -> hello.o (二进制, 可重定位)
4. **链接 (ld):** hello.o + printf.o -> hello (二进制, 可执行)

### 链接又是什么呢？
链接的两大核心功能是：
1. **符号解析 (Symbol Resolution):** 只要是引用，就要找到定义。
    
2. **重定位 (Relocation):** 把代码和数据拼在一起，确定最终内存地址

### 我们为什么需要链接（ benefits )

1. 模块化
2. 效率 对于时间与空间都可以进行提升。

## 目标文件与 ELF 格式

### 目标文件的三种形式

- **可重定位目标文件 (.o):** 包含二进制代码和数据，可以在编译时与其他 .o 文件合并。
    
- **可执行目标文件 (a.out / exe):** 包含二进制代码和数据，可以直接复制到内存并执行。
    
- **共享目标文件 (.so):** 一种特殊的 .o，可以在加载或运行时动态加载（后面章节会细讲）。

### ELF 文件的核心结构

- **ELF Header:** 包含字长、字节序、文件类型等元数据。
    ![[Pasted image 20251208204057.png]]
- **.text:** 已编译的机器代码（Machine Code）。
    
- **.data:** **已初始化**的全局变量和静态变量 (static)。
    
- **.bss:** **未初始化**的全局变量和静态变量。
    
    - 重点： 它在磁盘文件中**不占据实际空间**，仅仅是一个占位符。运行是初始化为 0。
        
    - 名字由来： Block Started by Symbol（汇编语言的历史遗留术语）。
                Better Saved Section （doge）
        
- **.symtab:** **符号表 (Symbol Table)**。存放程序中定义和引用的函数和全局变量的信息。
- **.rel：重定位条目（Relocation Label）**。只在.o中有，可执行文件中被移除|。

> ❓ **思考：** 为什么局部变量（Local variables）不在 .data 或 .bss 节中？  
> （答案提示：局部变量在运行时由栈 Stack 管理，不存储在目标文件中。）

### 视图的对比 ？

- **链接视图 (Linking View):**
    
    - **谁在看？** 静态链接器 (ld)。
        
    - **关注点：** **节 (Sections)**。比如 .text, .data, .bss。
        
    - **目的：** 为了把不同文件的同类节合并在一起（重定位）。
        
    - **关键索引：** **节头表 (Section Header Table)**。
        
- **执行视图 (Execution View):**
    
    - **谁在看？** 操作系统加载器 (Loader)。
        
    - **关注点：** **段 (Segments)**。
        
    - **目的：** 为了把文件映射到内存。加载器不管你哪里是 .text 哪里是 .rodata，它只关心**权限**。它会把所有“只读”的节打包成一个“只读代码段”，把所有“可读写”的节打包成一个“读写数据段”。
        
    - **关键索引：** **程序头表 (Program Header Table)** (也就是 PPT 里的段头表)。

## 符号解析的规则

- **符号分类：** Global (全局), External (外部), Local (静态局部).
    
- **强弱符号 (Strong vs Weak):**
    
    - **强：** 函数, 已初始化的全局变量。
        
    - **弱：** 未初始化的全局变量。
        
- **⚠️ 三大黄金法则 (必须背诵)：**
    
    1. 不能有两个强符号 (Error: Multiple definition).
        
    2. 强 + 弱 -> 选**强**。
        
    3. 弱 + 弱 -> **随机**选一个 (极度危险！容易覆盖内存)。
        
- **静态库 (.a Archive) 的解析逻辑 ：**
    
    - 链接器从左到右扫描 .o 和 .a 文件。
        
    - **重要坑点：** 库文件必须放在命令行的**最后**！(因为链接器如果先看到库，此时还没看到引用它的代码，就会丢弃库里的符号，导致后面报错 Undefined Reference)。

>[! note] 中间的解析逻辑
>类似于用三个存储空间，分别存储我们需要链接的目标文件，已定义与未定的。

## 重定位的计算

重定位我们需要掌握的有两种引用的方式：
1. 相对引用（个人觉得主要是针对于函数的 call）
2. 绝对引用 （个人觉得是针对于全局变量什么的）

- **核心任务：** 这里的 call sum 到底跳到哪？
    
- **关键公式 (PC相对寻址)：**  
    
    ```
    Target=PC+Offset
    ```
    
- **计算步骤：**
    
    1. ref_addr = 当前指令中空位的地址。
        
    2. *ref_ptr (要填的值) = ADDR(sum) - ref_addr + addend。
        
- **为什么 addend 通常是 -4？**
    
    - 因为 CPU 执行时，PC 已经指向了**下一条指令**，多走了 4 个字节，计算相对距离时要减回来。
